Partie 2

Objectif pédagogique

À la fin de cet épisode, vous serez capable de créer la structure HTML5 de départ d'un véritable portfolio professionnel.

Ce que vous saurez faire

  • Créer un dossier de projet bien rangé et un fichier index.html qui s'ouvre dans un navigateur.
  • Expliquer à quoi sert chaque partie d'une page : la déclaration, la racine, l'en-tête invisible et le corps visible.
  • Écrire une balise, lui ajouter des attributs, et la refermer correctement.
  • Décrire la page aux moteurs de recherche grâce aux métadonnées.
  • Charger des fichiers externes (polices, bibliothèques, icônes) depuis Internet.
  • Afficher une petite icône dans l'onglet du navigateur.
  • Ouvrir les outils de développement du navigateur pour vérifier votre travail et repérer une erreur.
  • Retrouver vous-même, dans une documentation officielle, pourquoi une ligne s'écrit comme ça.

Les mots à connaître avant de commencer

Chaque mot technique de l'épisode est expliqué ici, la première fois qu'il apparaît. Revenez à cette liste dès qu'un mot vous bloque.

HTML
Le langage qui décrit le contenu d'une page web : « ceci est un titre », « ceci est un paragraphe ». Ce n'est pas un langage de programmation : il ne calcule rien, il structure.
HTML5
La version actuelle de HTML. Elle a ajouté des balises qui donnent du sens à la page, comme <main>. Aujourd'hui, on dit souvent simplement « HTML ».
Balise
Un mot entre chevrons, comme <h1>. La plupart vont par deux : une balise ouvrante <h1> et une balise fermante </h1>, avec une barre oblique. Ce qui est entre les deux est le contenu.
Élément
L'ensemble « balise ouvrante + contenu + balise fermante ». Par exemple <h1>Lucas Moreau</h1> est un élément.
Attribut
Une information supplémentaire écrite dans la balise ouvrante, sous la forme nom="valeur". Exemple : lang="fr".
Commentaire
Un texte écrit entre <!-- et --> : le navigateur l'ignore complètement. Il sert à laisser des notes aux humains qui lisent le code.
CSS
Le langage qui décrit l'apparence : couleurs, polices, espacements. Nous l'écrirons à partir de l'épisode 2.
JavaScript
Le langage de programmation du navigateur : il rend la page interactive (boutons, animations…). Dans cet épisode, il n'apparaît que dans le petit fichier config.js.
URL
L'adresse d'un fichier ou d'une page, comme https://fonts.googleapis.com. Une seule lettre fausse et le fichier n'est plus trouvé.
Chemin de fichier
L'adresse d'un fichier dans votre dossier. images/favicon-32x32.png veut dire : « entre dans le dossier images, puis prends le fichier favicon-32x32.png ».
Bibliothèque
Du code déjà écrit par d'autres développeurs, que l'on réutilise au lieu de tout refaire. Bootstrap, Font Awesome, Animate.css et PDF.js sont des bibliothèques.
CDN
Content Delivery Network, « réseau de distribution de contenu » : des serveurs répartis dans le monde qui stockent des fichiers populaires (comme Bootstrap) et vous les envoient depuis le serveur le plus proche.
Métadonnées
Des « données sur les données » : des informations à propos de la page (sa langue, sa description, son auteur), que le visiteur ne voit pas directement.
SEO
Search Engine Optimization, le référencement : tout ce qui aide une page à être bien comprise et bien classée par les moteurs de recherche comme Google.
Responsive
Une page « responsive » (adaptative) s'ajuste à la taille de l'écran : ordinateur, tablette ou smartphone.
Accessibilité
Le fait qu'une page soit utilisable par tout le monde, y compris les personnes malvoyantes qui utilisent un lecteur d'écran (un logiciel qui lit la page à voix haute) ou celles qui naviguent uniquement au clavier.
Favicon
La petite icône affichée dans l'onglet du navigateur, à côté du titre de la page.
DOM
Document Object Model : la représentation de la page que le navigateur construit en mémoire à partir de votre HTML. C'est ce que vous voyez dans l'onglet « Éléments » des outils de développement.
API
Application Programming Interface : un ensemble de commandes prêtes à l'emploi qu'un programme met à disposition des autres. Exemple : console.log() fait partie de l'API du navigateur. Nous l'utiliserons dans config.js.
Outils de développement
Un panneau caché dans tous les navigateurs, qui montre l'intérieur de la page. On l'ouvre avec la touche F12 (ou Ctrl+Maj+I sous Windows, Cmd+Option+I sur Mac). On y trouve les onglets Éléments, Console et Réseau.

Partie 4

Où trouver les informations ?

Un développeur ne connaît pas tout par cœur : il sait où chercher. Voici les sources officielles qui ont permis d'écrire chaque ligne de l'épisode. Les liens marqués ↗ s'ouvrent dans un nouvel onglet.

🔎 Reconnaître une source officielle

  • Le site appartient à l'organisme qui crée l'outil : getbootstrap.com pour Bootstrap, fontawesome.com pour Font Awesome, mozilla.github.io pour PDF.js.
  • Ou à un organisme de référence reconnu : le WHATWG et le W3C écrivent les normes du Web ; MDN (Mozilla) est la documentation de référence utilisée par les professionnels.
  • La documentation indique la version dont elle parle (ex. « Bootstrap v5.3 »).
  • L'adresse commence par https:// et le nom de domaine est bien orthographié.

⚠️ Pourquoi éviter de copier du code d'une source inconnue ?

Une ligne <script src="…"> fait exécuter, dans le navigateur de chaque visiteur, le programme qui se trouve à cette adresse. Si l'adresse provient d'un site douteux, ce programme peut afficher des publicités, espionner les saisies ou rediriger vos visiteurs. Copiez donc les adresses des bibliothèques uniquement depuis leur site officiel ou un CDN reconnu (jsDelivr, cdnjs), et gardez un numéro de version précis, comme bootstrap@5.3.0, pour que le fichier ne change pas sans prévenir.

Partie 5

Construction étape par étape

On construit le fichier petit à petit. À chaque étape, suivez toujours le même cycle :

  1. 1 Écrire les lignes
  2. 2 Enregistrer : Ctrl+S (Cmd+S sur Mac)
  3. 3 Actualiser le navigateur : F5
  4. 4 Observer le résultat
  5. 5 Comprendre ce qui a changé

💡 L'indentation

L'indentation, ce sont les espaces au début d'une ligne. Ils ne changent rien pour le navigateur, mais ils montrent aux humains quelle balise est « rangée » dans quelle autre. Règle de la série : 2 espaces de plus à chaque niveau. Dans VS Code, la touche Tab les ajoute pour vous.

Étape 1 Créer le fichier index.html

Faites : dans VS Code, ouvrez le dossier portfolio-tssr et créez le fichier index.html. Laissez-le vide, enregistrez, puis double-cliquez dessus dans l'Explorateur de fichiers.

Vous voyez : une page entièrement blanche. L'onglet affiche « index.html ». C'est normal : le fichier existe, mais il est vide.

Étape 2 Déclarer HTML5 avec <!DOCTYPE html>

Écrivez sur la toute première ligne :

<!DOCTYPE html>

Vous voyez : toujours une page blanche. Pour vérifier l'effet, ouvrez les outils de développement (F12), cliquez sur l'onglet Console, tapez document.compatMode puis Entrée. La réponse 'CSS1Compat' signifie « mode standard » : le navigateur a compris qu'il s'agit d'une page HTML5 moderne.

Étape 3 Créer <html>, <head> et <body>, avec un premier contenu

Écrivez sous le DOCTYPE :

<html>
<head>
</head>
<body>
      <h1>Lucas Moreau</h1>
      <p>Technicien Supérieur Systèmes &amp; Réseaux</p>
</body>
</html>

Vous voyez : « Lucas Moreau » en grand, et le métier en dessous, dans une police avec empattements (petits « pieds » au bas des lettres, comme Times New Roman). C'est le style par défaut du navigateur. Si « Supérieur » s'affiche avec des caractères étranges, pas de panique : l'étape 7 va le corriger.

Comprendre : <head> contient ce que le visiteur ne voit pas, <body> ce qu'il voit. &amp; est la façon propre d'écrire le caractère « & » en HTML.

Étape 4 Ajouter lang="fr"

Modifiez la balise ouvrante :

<html lang="fr">

Vous voyez : rien ne change à l'écran. Mais dans F12 › onglet Éléments, la balise <html lang="fr"> apparaît. Le navigateur sait désormais que la page est en français : il ne vous proposera plus de la traduire, et un lecteur d'écran la lira avec une voix française.

Étape 5 Ajouter data-theme="dark" 
<html lang="fr" data-theme="dark">

Vous voyez : la page reste blanche. C'est voulu. Cet attribut est une étiquette que nous avons inventée ; aucun CSS ne la lit encore. À l'épisode 2, nos couleurs viendront s'y brancher, et plus tard un bouton JavaScript fera passer sa valeur de dark à light.

Étape 6 Ajouter dir="ltr" 
<html lang="fr" data-theme="dark" dir="ltr">

Expérience : remplacez provisoirement ltr par rtl, enregistrez, actualisez : le texte se colle à droite, comme pour une page en arabe ou en hébreu. Remettez ltr (de gauche à droite) : le texte revient à gauche.

Étape 7 Ajouter l'encodage <meta charset="UTF-8" />

Écrivez juste après <head>, en décalant de 2 espaces :

  <meta charset="UTF-8" />

Vous voyez : les accents de « Supérieur » et « Réseaux » s'affichent correctement, quel que soit le navigateur.

Étape 8 Ajouter le titre de l'onglet <title>

Écrivez juste avant </head>. Cette ligne restera toujours la dernière du <head> : les étapes suivantes s'insèrent au-dessus d'elle.

  <title>Portfolio TSSR | Recherche d'emploi – Technicien Systèmes &amp; Réseaux · MODE 83 Draguignan</title>

Vous voyez : l'onglet du navigateur n'affiche plus « index.html » mais « Portfolio TSSR | Recherche d'emploi… ». Survolez l'onglet avec la souris pour lire le titre entier.

Étape 9 Ajouter la balise viewport (responsive)

Écrivez sous la ligne charset :

  <meta name="viewport" content="width=device-width, initial-scale=1.0" />

Pour l'observer : dans F12, cliquez sur l'icône représentant un téléphone et une tablette (ou Ctrl+Maj+M dans Chrome et Edge) et choisissez un modèle de smartphone. Le texte a une taille lisible. Sans cette ligne, un vrai téléphone afficherait la page comme un écran d'ordinateur rétréci, avec un texte minuscule.

Étape 10 Ajouter les métadonnées : description, mots-clés, robots, couleur, auteur

Écrivez les lignes 6 à 10 sous le viewport (copiez-les depuis la partie « Code complet » pour éviter les fautes de frappe dans les longs textes).

Faites un clic droit sur la page › Afficher le code source de la page (Ctrl+U) : vos lignes y sont. Sur un smartphone Android avec Chrome, la barre d'adresse prendrait la couleur bleu nuit #060d1a.

Étape 11 Charger les polices Google Fonts

Laissez une ligne vide après l'auteur, puis écrivez les lignes 12 à 14 (copiez la longue adresse de la ligne 14 depuis le code complet).

  <link rel="preconnect" href="https://fonts.googleapis.com" />
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />

Pour l'observer : le texte ne change pas encore de police, c'est normal : le CSS qui utilisera ces polices arrive à l'épisode 2. Vérifiez le chargement : F12 › onglet Réseau, puis F5. Une ligne css2?family=Syne… avec le statut 200 veut dire « fichier reçu ».

Étape 12 Charger Bootstrap

Vous voyez : dans F12 › Console, le message config.js chargé ✔. La preuve que les deux fichiers communiquent.

Étape 16 Ajouter les 4 favicons

Partie 6 · la plus importante

Explication ligne par ligne

Chaque fiche répond à quatre questions : Quoi ? (ce que fait la ligne), Pourquoi ? (pourquoi elle est nécessaire), Comment ? (comment elle s'écrit, morceau par morceau) et Où ? (où retrouver l'information). Les numéros correspondent au code complet.

🧩 Une ligne = plusieurs informations

Une seule ligne de code peut contenir plusieurs informations différentes. La ligne 2, par exemple, en contient quatre : une balise et trois attributs. C'est pourquoi les fiches les plus riches ont une partie Décomposition, qui découpe la ligne morceau par morceau.

Le fichier index.html

Lignes vides (11, 15, 19, 22, 27 et 30) : elles ne font rien pour le navigateur. Elles aèrent le code en séparant les groupes de lignes, comme des paragraphes dans un texte.

Ligne 1 La déclaration HTML5 
<!DOCTYPE html>

Ce que fait cette ligne

Elle annonce au navigateur : « ce fichier est une page HTML moderne (HTML5) ».

Pourquoi elle est nécessaire

Le navigateur sait afficher des pages écrites il y a 25 ans comme des pages récentes. Cette ligne lui dit d'appliquer les règles actuelles, appelées « mode standard ».

Si on la supprimait

Le navigateur passerait en mode quirks (« mode bizarreries ») : il imiterait d'anciens navigateurs, et certaines règles CSS des épisodes suivants seraient mal interprétées (tailles, marges). Vérification : dans la Console, document.compatMode afficherait 'BackCompat' au lieu de 'CSS1Compat'.

Le vocabulaire

<! … >
Une instruction spéciale, pas une balise ordinaire : elle n'a pas de balise fermante.
DOCTYPE
Abréviation de document type, « type de document ». Majuscules ou minuscules : les deux fonctionnent.
html
Le type annoncé : HTML, dans sa version actuelle.

Ligne 2 La balise racine et ses trois attributs

Ce que fait cette ligne

Elle ouvre la balise <html>, qui va contenir toute la page, et lui donne trois informations : la langue, le thème et le sens de lecture.

Pourquoi elle est nécessaire

Toutes les autres balises doivent être rangées dans une seule boîte principale, appelée la racine. Ses attributs s'appliquent à toute la page.

Si on la supprimait

Le navigateur recréerait une racine tout seul, mais sans aucun des trois attributs : la langue serait inconnue, notre futur thème sombre n'aurait plus de point d'accroche, et la page serait moins bien comprise par les lecteurs d'écran.

Décomposition

  1. <html
    La balise racine. Le chevron < ouvre la balise, html est son nom. Elle sera refermée tout en bas du fichier, ligne 39, par </html>.
  2. lang="fr"
    La langue de la page. lang est le nom de l'attribut, fr sa valeur (le code officiel du français). Les lecteurs d'écran choisissent la bonne voix, les navigateurs ne proposent pas de traduire, Google sait à quel public s'adresse la page.
  3. data-theme="dark"
    Notre étiquette de thème. Tous les attributs qui commencent par data- sont des attributs personnalisés : on invente la suite du nom (ici theme). Attention : Bootstrap utilise son propre attribut, data-bs-theme ; notre data-theme ne le concerne pas.
  4. dir="ltr"
    Le sens de lecture. dir pour « direction », ltr pour left to right, « de gauche à droite », comme en français. L'inverse serait rtl, pour l'arabe ou l'hébreu.
  5. >
    Fin de la balise ouvrante. Les attributs sont séparés par un espace et toujours écrits entre le nom de la balise et ce chevron.

Ligne 14 Charger les trois polices

Ce que fait cette ligne

  2. family=Syne:wght@400;500;600;700;800
    Première police : Syne, en 5 épaisseurs (wght = weight, « graisse »). 400 = normal, 700 = gras, 800 = très gras. Les valeurs sont séparées par des points-virgules.

    Afficher le texte tout de suite avec une police de secours, puis échanger (swap) dès que la vraie police est arrivée. Le visiteur n'attend jamais devant un écran vide.
  6. rel="stylesheet"
    La relation : ce fichier est une feuille de style. Ici, rel est écrit après href : l'ordre des attributs n'a aucune importance.

Ligne 28 Le titre de l'onglet 
  <title>Portfolio TSSR | Recherche d'emploi – Technicien Systèmes &amp; Réseaux · MODE 83 Draguignan</title>

Ce que fait cette ligne

Elle donne son titre à la page. Il s'affiche dans l'onglet, dans les favoris et comme lien cliquable dans les résultats de Google.

Pourquoi elle est nécessaire

C'est obligatoire dans une page HTML valide, et c'est le texte le plus important pour les moteurs de recherche et les lecteurs d'écran (c'est la première chose annoncée à l'ouverture de la page). On y met le métier, l'objectif et la localisation.

Si on la supprimait

Décomposition

  1. <title> … </title>
    Une balise ouvrante et une fermante, avec le texte du titre entre les deux.
  2. &amp;
    Une entité HTML (ou « référence de caractère ») : la façon propre d'écrire le caractère &. En HTML, & annonce le début d'une entité ; pour afficher un vrai « & », on écrit donc &amp; (ampersand). Elle commence par & et finit toujours par un point-virgule.
  3. |, –, ·
    Des séparateurs visuels (barre verticale, tiret, point médian) : ils découpent le titre en morceaux lisibles.

Elle ouvre la zone de contenu principal de la page et lui donne un identifiant : main-content.

Ligne 33 Le conteneur Bootstrap 
    <div class="container">

Ce que fait cette ligne

Elle crée une boîte qui centre le contenu et limite sa largeur selon la taille de l'écran.

Pourquoi elle est nécessaire

Sur un très grand écran, un texte qui va d'un bord à l'autre devient illisible. La classe container de Bootstrap fixe une largeur maximale adaptée à chaque écran : 100 % sur un smartphone, puis 540, 720, 960, 1140 et jusqu'à 1320 pixels sur les grands écrans.

Si on la supprimait

Le texte serait collé au bord gauche de la fenêtre, sans marge, quelle que soit la taille de l'écran.

Décomposition

  1. <div
    Une boîte générique (division). Elle n'a aucun sens particulier : elle sert à regrouper et à mettre en page.
  2. class="container"
    Une classe : une étiquette réutilisable qui relie l'élément à un style. Contrairement à un id, la même classe peut être utilisée sur plusieurs éléments. Le style de container est fourni par Bootstrap (ligne 16).

Où trouver l'information

Le container, c'est le conteneur du camion : il donne une forme standard au chargement.

Partie 10

Si ça ne fonctionne pas

Une erreur n'est pas un échec : c'est une information. Voici les erreurs les plus fréquentes, du symptôme à la solution.

Erreur 1 Le fichier s'appelle index.html.txt

Symptôme
Le navigateur affiche le code au lieu de la page, ou le fichier s'ouvre dans le Bloc-notes.
Cause
Windows cache les extensions : le fichier a été enregistré comme texte.
Solution
Explorateur › Affichage › cocher Extensions de noms de fichiers, puis renommer en index.html. Le plus sûr : créer le fichier depuis VS Code.
Vérification
Dans VS Code, l'icône du fichier est orange avec <>, et le coin en bas à droite indique « HTML ».

Erreur 2 Une balise mal fermée

Symptôme
Le métier s'affiche en énorme, comme le nom, ou du texte comme </h1 apparaît à l'écran.
Cause
Un chevron >, une barre oblique / ou une balise fermante entière a été oubliée, par exemple <h1>Lucas Moreau<h1>.
Solution
Comparez la ligne avec la fiche correspondante. Chaque balise ouverte doit avoir sa fermante, dans l'ordre inverse.
Vérification
VS Code colore la balise partenaire quand vous cliquez sur une balise. Le validateur du W3C indique le numéro de la ligne fautive.

Erreur 3 Une URL externe mal copiée

Symptôme
La police reste à empattements : Bootstrap ne s'applique pas.
Cause
Une lettre manque ou est en trop dans l'adresse (par exemple bootstrap@5.3.0 devenu bootstrap@5.30).
Solution
Recopiez l'adresse depuis le bouton « Copier » de la partie Code complet, plutôt que de la retaper.
Vérification
F12 › Réseau › F5 : la ligne fautive apparaît en rouge avec le statut 404 (introuvable).

Erreur 4 Le dossier images n'est pas au bon endroit

Symptôme
Aucun favicon dans l'onglet.
Cause
Le dossier images est ailleurs (dans ressources, sur le Bureau…) alors que le chemin images/… le cherche à côté de index.html.
Solution
Déplacez le dossier images directement dans portfolio-tssr.
Vérification
Le panneau de gauche de VS Code doit ressembler à l'arborescence de la partie 3.

Erreur 5 Le nom du favicon est incorrect

Symptôme
Pas de favicon, alors que le dossier est au bon endroit.
Cause
Une différence entre le nom écrit dans le code et le vrai nom : favicon-32X32.png (X majuscule), favicon_32x32.png (tiret bas), extension .jpg au lieu de .png…

Erreur 6 Un caractère supprimé accidentellement

Symptôme
Une partie de la page disparaît, ou un morceau de code s'affiche à l'écran.
Cause
Un guillemet " ou un chevron effacé : le navigateur ne sait plus où finit l'attribut ou la balise, et « avale » la suite.
Solution
Dans VS Code, regardez les couleurs : après un guillemet manquant, toute la suite prend la couleur d'un texte entre guillemets. Remontez jusqu'à l'endroit où les couleurs changent.
Vérification
